    1. About Pankaj

    Pankaj Doharey is an AI systems architect, CTO, and fullstack technology leader with 17 years of experience building production software.

    His career spans voice AI, generative media, fintech, healthcare logistics, developer tooling, data platforms, and high-concurrency web applications. He combines hands-on engineering with architecture, technical leadership, and the day-to-day work of turning ambiguous product requirements into maintainable systems.

    Today, he focuses on production AI rather than prototype-only demos: real-time voice agents, retrieval-augmented workflows, diffusion-backed creative tooling, and infrastructure that keeps model-backed products observable, fast, and reliable.

    GitHub · LinkedIn · Email

    2. From web applications to AI and telecom

    The career began with web applications: PHP, Drupal, Zen Cart, and client- facing products. It grew through Ruby on Rails systems, analytics platforms, ETL pipelines, logistics software, and developer tools.

    Over time, the work moved into systems where software has to coordinate more than a browser request. That includes real-time tracking, financial origination, healthcare logistics, GPU-backed image generation, and telecom infrastructure.

    Telecom and voice systems still use a great deal of web technology: APIs, databases, queues, distributed services, cloud infrastructure, and web frontends. The difference is that the system must also handle live audio, signalling, provider integrations, strict latency budgets, and failures while people are actively using it.

    That path led naturally to AI systems. The central engineering questions stay the same: where state lives, how services fail, how data moves, and how to keep complex systems understandable.

    7. How I work

    7.1. Stay close to the implementation

    Architecture is strongest when it is informed by real code, production failures, operational data, and the experience of the people using the system.

    7.2. Design for the real constraints

    Latency, cost, reliability, model quality, provider failures, data movement, and human review are part of the product — not details to postpone.

    7.3. Make complex systems legible

    Good abstractions, clear boundaries, observability, and documentation allow a team to move quickly without losing control of the system.

    7.4. Teach while building

    Pankaj uses architecture reviews, paired programming, mentoring, and writing to make hard-won engineering knowledge reusable.

    8. About Self dot send

    Self dot send is Pankaj's engineering notebook. It covers the ideas and implementation details behind programming languages, web and distributed systems, telecom and voice infrastructure, developer tools, and applied AI.

    Most posts begin with a problem encountered while building software. The goal is to explain the model, show the implementation, and record the trade-offs that are easy to lose once the code works.

    Posts are written in Org files and published through an editor-first workflow using AOG, a customized Emacs Org-mode static publishing system.
